Quickstart

Two fast ways to try the project: containerized builds or local/native builds.

🐳 Containerized (Docker)

Build optimized container images for Node and Python development environments.

make node
make python

Requires: Docker installed locally or in your environment.

⚙️ Native C Demo

Build a lightweight TCP server and explore the gateway demo locally.

# Build lightweight server for testing
gcc -std=c11 -Wall -Wextra -O2 -o server/server server/server.c

# Run
./server/server

Requires: gcc/clang, GNU make, and standard POSIX tools.

🎮 C++ Playground

Advanced C++ demos that integrate with KLEE and CRAXExpr for constraint solving.

# Build inside dev container (recommended)
docker run -it makeuniversal-dev bash
make playground

Note: Requires project dependencies (KLEE, CRAXExpr). Easier inside the container.

  • 📚 Docs & whitepaper

    GitHub Actions workflows for automatic static docs deployment.

  • 🔐 Security-focused

    PROXY protocol handling, robust parsing, and auditable installer scripts.

⚠️ Security Notice

This project contains networking code (PROXY protocol parsing) and system-level installer scripts. Always audit code before running on production systems.

  • Review server/server.c and proxy protocol handling in server/rsc/@stud/Proxy-Protocol.c
  • Read Lmlm.dev/install.sh before executing with sudo
  • Test in isolated environments first

Contribute

We welcome contributions! Here's how to get started.

Development Workflow

  1. Fork the repository on GitHub
  2. Create a feature branch: git checkout -b feature/your-feature
  3. Make your changes and test thoroughly
  4. Run linting and analysis:
    • shellcheck on shell scripts
    • cppcheck or clang-tidy on C/C++ code
  5. Commit with clear, descriptive messages
  6. Push to your fork and open a Pull Request against main

Code Standards

  • C/C++: Follow ISO C11/C17 and modern C++ practices
  • Shell: POSIX-compliant, ShellCheck-clean scripts
  • Makefile: Portable, well-documented targets
  • Documentation: Clear README sections, inline comments for complex logic

Please see CONTRIBUTING.md for detailed guidelines on testing, commit messages, and PR expectations.
